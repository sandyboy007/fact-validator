# Fact Validator: Final Methods and Reproducibility

## Evaluation boundary

The repository contains two related but distinct artifacts:

1. **Fact Validator live application** - the implemented open-web system. It
   accepts text or a URL and can execute SerpAPI retrieval, domain-level
   credibility scoring, SentenceTransformer reranking, optional Ollama debate,
   persistence, caching, and report generation.
2. **FactValidator-Proxy** - the deterministic model evaluated on the frozen
   5,000-claim benchmark. It combines a lexical model, category-level priors,
   heuristic semantic signals, a deterministic debate rule, and a quality
   filter.

The 5,000-claim experiment does **not** execute live SerpAPI retrieval, live
domain credibility scoring, SentenceTransformer reranking, or Ollama debate
for every claim. Results from that experiment must be labelled proxy results.
The live application is supported separately through implementation evidence,
software tests, and bounded operational demonstrations.

## Data

The frozen experiment uses 19,983 unique normalized claims:

| Split | Claims |
|---|---:|
| Train | 11,986 |
| Validation | 2,997 |
| Test | 5,000 |

The benchmark combines FEVER, LIAR, SciFact, and the PUBHEALTH
`health_fact` dataset. The health dataset is stored under the legacy
`healthver` compatibility filename; it is not the original HealthVer release.

The authoritative split files are:

- `data/benchmarks/splits_5000/train.json`
- `data/benchmarks/splits_5000/val.json`
- `data/benchmarks/splits_5000/test.json`

Exact normalized claim duplicates are excluded across the frozen partitions.
The run manifest records SHA-256 hashes for the split and prediction files.

## Proxy model

`services/api/Scripts/run_ablation_study.py` trains the lexical component from
the frozen training split and evaluates these deterministic variants:

- `full_proxy`
- `ablate_credibility`
- `ablate_semantic_rerank`
- `ablate_debate`
- `ablate_quality_filter`
- `tune_fever` (exploratory dataset-aware adjustment)

The name `full_proxy` is intentionally retained. Its credibility signal is a
category-level prior that mimics one effect of source trust; it is not live
domain scoring. Its semantic signal is heuristic; it is not a
SentenceTransformer execution. Its debate stage is deterministic arbitration;
it is not Ollama multi-agent debate.

## Baselines

The proxy is compared with frozen majority, length, keyword, sentiment, and
seeded random baselines. Every system must produce exactly 5,000 predictions
with the same claim identifiers.

## Metrics and statistics

The final report includes:

- accuracy and Wilson 95% confidence intervals;
- class precision, recall, and F1;
- macro-F1;
- confusion matrix;
- per-dataset accuracy;
- exact two-sided McNemar tests on paired correctness;
- paired-bootstrap confidence intervals with seed 42;
- Holm correction across multiple comparisons;
- matched-pair odds ratios and paired risk differences.

The proxy stores one heuristic confidence score rather than a complete
multiclass probability vector. Confidence analysis is therefore labelled a
**raw-score calibration diagnostic**. A proper multiclass Brier score cannot
be calculated until every prediction stores `prob_supported`, `prob_refuted`,
and `prob_nei`.

## Reproduction

From the repository root:

```bash
python services/api/Scripts/build_thesis_run_manifest.py
python services/api/Scripts/run_thesis_statistics.py
pytest services/api/tests -q
```

Generated files are stored under `data/benchmarks/results_5000/`. Python
dependencies are defined in `services/api/requirements.in` and locked with
hashes in `services/api/requirements.lock`. The expected Python version is
recorded in `.python-version`.

## Interpretation rules

- Do not call `full_proxy` the live or complete application pipeline.
- Do not claim direct empirical superiority over FacTool, FEVER systems,
  SciFact systems, or factual-error-correction systems without a matched
  evaluation.
- The no-debate proxy records higher observed accuracy than `full_proxy`.
- Marginal unadjusted p-values against simple baselines are not presented as
  robust superiority after multiple-comparison correction.
- Operational cost and throughput values are projections unless generated by
  a controlled repeated-run load benchmark.
